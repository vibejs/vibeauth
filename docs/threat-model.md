# Threat model

Assets include credentials, cookies, session state, recovery/MFA material, provider secrets,
and tenant data. Trust boundaries are browser ↔ HTTP server, server ↔ Better Auth/database,
provider/email callbacks, and organization/resource ownership. The browser and all URL/body
claims are untrusted. Better Auth is the authentication engine; VibeAuth must preserve its
protocol behavior and correctly apply business authorization.

| Threat                                      | Protective mechanism / residual boundary                                                                                                      | Relevant verification                                                                                              |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Session hijacking                           | Better Auth signed, HttpOnly cookies; HTTPS Secure and Lax defaults; secrets never duplicated into custom storage                             | `src/server/auth.test.ts`: forged cookies, secure attributes, real cookie lifecycle                                |
| Session fixation                            | Better Auth issues sessions; login after logout creates a new session; no client-selected token                                               | Auth lifecycle test checks fresh cookies                                                                           |
| CSRF                                        | Better Auth protocol checks enabled; unsafe business requests require an exact Origin after authentication                                    | Real cross-site form/origin rejection; `origin.test.ts`; SaaS mutation without Origin                              |
| Account enumeration                         | Generic signup/recovery/login UI, native token delivery, no lookup endpoint                                                                   | Credentials composition and existing/missing-account recovery response comparison                                  |
| Brute-force credentials                     | Official persistent limiter and MFA failure controls; topology-specific abuse monitoring remains application-owned                            | Real 429 test; invalid password and MFA code tests                                                                 |
| OAuth callback manipulation                 | Official handler owns state and applicable PKCE; no custom callback controller                                                                | Invalid state/code and unsafe callback tests; no fake successful provider flow                                     |
| Open redirects                              | Better Auth trusted callbacks plus conservative local return/fallback validation                                                              | Auth unsafe callback test; router tests include encoded separators, controls, dot segments and unsafe fallbacks    |
| Account linking confusion                   | Official linking policy and verified provider identity; review trusted-provider configuration                                                 | No custom linking or claimed live-provider linking test; manual procedure in social guide                          |
| Session revocation races                    | Business reads bypass cookie cache, request-only deduplication, explicit fresh reads; already authorized writes need transaction-bound checks | Logout/revoke/reset old-cookie rejection; forced-read failure race test                                            |
| Cross-tenant access                         | Official membership/role checks plus tenant-scoped SQL for reads and resource updates                                                         | `test/saas.test.ts`: foreign organization and resource IDs denied                                                  |
| Broken authorization / privilege escalation | Explicit policies; Admin/Organization role mutations stay native and server-side                                                              | Unauthorized role changes and another user's session revocation denied                                             |
| Client-only guards                          | Server CanActivate checks remain mandatory; router is UX only                                                                                 | Anonymous/forbidden direct Fetch and typed contract tests                                                          |
| Authentication state races                  | Official session atom cancellation, latest navigation checks, identity recheck after async policies                                           | Delayed stale client responses, concurrent navigation, account switching, multi-instance tests                     |
| Cookie misconfiguration                     | Exact external origin, explicit HTTPS flag, no automatic NODE_ENV weakening, no wildcard origins                                              | Secure cookie checks, example configuration tests, real browser cookie flow                                        |
| Credentials in logs                         | Adapter never reads passwords; no token-bearing context; private explicit local mail transport; keep proxy/access logs redacted               | Browser graph/package checks and context token assertions; operational log configuration remains application-owned |
| MFA challenge bypass                        | No authenticated session during challenge; server verifies actual cookie; no assumption that OAuth/passkey was MFA-gated                      | TOTP/backup tests and protected API rejection during challenge                                                     |
| Stale user query caches                     | User/organization keys, cancel/clear on identity change, no QueryCache auth authority                                                         | Native reactive isolation tests and reviewed example integration; persistence must be scoped by the application    |

These tests prove adapter behavior against Better Auth's real APIs. They do not prove Better
Auth's cryptography, external provider behavior, physical authenticator security, or every
application's authorization model. No independent security audit has been performed.
