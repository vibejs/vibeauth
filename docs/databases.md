# Databases and migrations

VibeAuth accepts Better Auth's configured instance, without importing a database driver.
The application chooses its official adapter. Do not hand-create auth tables from examples
or automatically migrate unknown databases on startup.

| Backend                      | Integration status                                                                                     |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ |
| SQLite / Node `DatabaseSync` | Real core, plugin, security, SaaS and example migration tests                                          |
| PostgreSQL / Drizzle         | Real signup/session/logout/login test on PGlite's embedded PostgreSQL engine, official Drizzle adapter |
| Network PostgreSQL           | Configuration documented; no external PostgreSQL service tested                                        |
| MySQL                        | Supported by Better Auth's database/Drizzle integration; not tested here                               |
| Prisma                       | Official adapter remains usable; not tested here                                                       |
| Cloudflare D1                | Upstream native integration investigated; deployment unverified here                                   |

## SQLite examples

`migrate` compiles Better Auth's migration plan to the example's `migration.sql`. Review and
back up before `migrate --apply`. Applying is explicit and targets `DATABASE_PATH`; startup
never migrates. The SaaS plan includes enabled plugin tables plus the application's project
table. Only the business table SQL is application-authored. Every auth/plugin column comes
from the official Better Auth migration generator.

The committed example SQL shows a fresh-database plan. Regenerate against the actual database
before an upgrade; do not assume an initial schema is an upgrade migration. Version and review
production migrations, rehearse rollback/restore and retain a backup. Do not enable a plugin
without migrating it.

## PostgreSQL with Drizzle

The checked test schema is generated by the official CLI:

```sh
pnpm exec auth generate --config test/postgres.config.ts --output test/generated/pg-schema.ts --yes
pnpm exec drizzle-kit generate
```

The test applies Drizzle's generated SQL to an isolated PGlite instance, then uses the real
Better Auth Drizzle adapter. For a deployed PostgreSQL database, configure your normal Drizzle
PostgreSQL driver, generate from your actual enabled plugins, and apply migrations with your
reviewed Drizzle workflow. PGlite verification does not prove network/TLS/pooling behavior.
[Official Drizzle integration](https://better-auth.com/docs/adapters/drizzle).

Use a shared persistent database and appropriately managed connection pool for multiple app
instances. Keep application transactions and resource constraints separate from auth schema
ownership. Do not substitute Node SQLite for a Worker D1 binding.
